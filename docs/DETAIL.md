# 手机连接选路

dsh-mobile-plugin 把「这台电脑有哪些地址可以连」报给手机，手机自己按顺序试。这个插件在电脑侧
替它做决定：**按实测延迟挑一条通道**，再把选择翻译成插件能理解的三件事——局域网候选的优先
地址、手填直连地址、直连隧道开关。

## 它解决什么

同一台电脑往往同时有多条可达路径：

| 通道 | 典型地址 | 特点 |
| --- | --- | --- |
| 局域网 | `192.168.70.27:18787` | 最快，但跨 VLAN、休眠、网卡改动时会断 |
| Tailscale | `100.64.26.27:18787` | 稳定，但流量会绕 VPN 的虚拟网卡 |
| 直连隧道 | 内置 tailcat | 兜底，打洞失败时要经公网节点中转，抖动明显 |
| 中转 | 自建 relay | 最后的兜底，延迟最高 |

dsh-mobile-plugin 的候选顺序是写死的（中转 → 局域网 → 手填直连 → IPv6 → Cloudflare → TCP →
自定义线路），手机端「按顺序挨个试，第一个通就用」。于是局域网那条一旦不可用，手机就退到慢
线路上，而且不会自己抢回来——这就是「明明在同一个局域网，ms 却时好时坏」的来源。

## 三种模式

- **局域网优先**：局域网健康就用它；不健康时依次退到 Tailscale、直连隧道、中转。
- **自动择优**：在健康通道里挑延迟最低的那条，只有明显更快（25% 以上）才切换，避免来回跳。
- **手动顺序**：完全按面板上的顺序走，前一条连续不健康（次数由阈值决定）才让位。

三种模式共用同一套健康判据：探测失败，或延迟超过该通道的「降级阈值」，算不健康。**不健康不
等于立刻切**——要连续达到「连续失败次数」才降级，否则一次抖动就会把手机推到更慢的线路上。
恢复到「恢复阈值」以下才切回来。

## 安全护栏

关掉直连隧道是逼手机走局域网的唯一手段，也是唯一能让手机彻底连不上的动作。所以它有四道闸：

1. 只有 `allowDisableTailcat` 打开时才允许关；
2. 局域网必须**实测健康**（不只是端口在监听）；
3. 手机最近确实通过局域网连过（读 `relay-device-credentials.json` 里的 `lastChannel`）；
4. 局域网入口近期没有崩过——每次自愈之后 10 分钟内都算「不稳」，这段时间先保住兜底。

任何一条不满足就保持隧道开着，并在面板上写明是哪一条拦下来的。

同理，手填的 **TCP 直连**如果指向 Tailscale 网段（`100.64.0.0/10`），在「局域网优先」下它就是
一条绕路候选，插件会一并清掉；指向其它地址（内网穿透域名等）的不动，那是用户自己的线路。

局域网入口（sidecar）挂掉时，插件会按限频（默认 30 秒一次）调用 dsh-mobile-plugin 的
`/api/relay/restart-sidecar` 自愈。

## 面板

打开 `http://127.0.0.1:3080/api/mobile-route/panel`（端口按你实际的 DSH Web 端口）：

- 顶部显示当前生效通道、原因、上次探测时间；
- 四条通道的实时延迟与状态；
- 三种模式切换、手动顺序上下移动、每条通道的降级 / 恢复阈值与连续失败次数；
- 三个开关：允许关隧道、自动重启 sidecar、观察模式；
- 最近 60 条事件。

「观察模式」只计算不执行，适合先看几天它想切到哪，确认判断合理再切到执行。

## 接口

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/mobile-route/state` | 配置、各通道状态、当前决策、事件 |
| POST | `/api/mobile-route/config` | 改配置（面板同款字段） |
| POST | `/api/mobile-route/action` | `probe` / `heal` / `reset` |
| GET | `/api/mobile-route/panel` | 配置面板 |

## 已知限制

- **手机端仍有自己的判断**。这个插件编排的是电脑侧上报的候选与隧道开关，手机 App 拿到之后
  怎么合并、什么时候重新探测，不在本插件控制范围内。它的作用是持续把「正确的答案」摆在手机
  面前，而不是替手机完成切换。
- **直连隧道的时延量不到**。它需要隧道密钥，电脑侧只能读插件报的 ready 状态，所以它不参与
  「谁更快」的比较，只作兜底候选。
- **Tailscale 地址只识别 `100.64.0.0/10`**。自定义 CGNAT 网段需要改代码。
- 配置持久化走 profile 的 configEditor，改完插件会重启一次，内存里的探测历史会清空。
