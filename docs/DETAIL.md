# 手机连接选路

dsh-mobile-plugin 把「这台电脑有哪些地址可以连」报给手机，手机自己按顺序试。这个插件在电脑侧
替它做决定：**按实测延迟与稳定性挑一条链路**，再把选择翻译成插件能理解的三件事——局域网候选
的优先地址、手填直连地址、直连隧道开关。

## 链路模型

链路是决策的最小单位，每条都有稳定 id，分属四类来源：

| 来源 | 链路 id 示例 | 说明 |
| --- | --- | --- |
| 局域网网卡 | `lan:192.168.1.2`、`lan:10.19.9.3` | 从本机网卡枚举的 RFC1918 地址，**支持多个 IP / 多块网卡**，手机在同一 Wi-Fi 里直连 |
| 局域网·Tailscale 网卡 | `lants:100.64.19.3` | `tailscale0` 这类 `100.64.0.0/10` 网卡地址，**算局域网内的一条线路**，通过 `manualLanUrl` 上报 |
| 插件单独配置 | `manual:lanUrl`、`manual:ipv4`、`manual:ipv6`、`manual:tcp` | dsh-mobile-plugin 设置里的手填直连 / 公网 IPv4 / IPv6 / TCP 直连 |
| 内置 | `tailcat`、`relay` | DSH 内置直连隧道（走公网节点中转，兜底）与中转（最后兜底） |

**两条 Tailscale 线路是分开的，这是明确的设计**：`tailscale0` 的 `100.64.19.3` 是本机网卡地址，
属于**局域网内的一条线路**（`lan-ts` 组），用 `manualLanUrl` 上报；而 DSH 内置的 `tailcat` 隧道
走公网节点中转，是**另一条独立线路**。两者独立参与排序、互不覆盖——选 Tailscale 网卡线路时
**不会**去关掉 DSH 隧道；只有选 RFC1918 局域网且满足四道安全闸时才可能关隧道。

**字段冲突**：`lan-ts` 线路与手填链路里的 `manual:lanUrl` 都占用 `manualLanUrl`，两者不能同时
生效，以当前选中的那条为准；面板顶部已显著提示。

**局域网地址按 dsh-mobile-plugin 的同款口径发现**：认 RFC1918 三段（10/8、172.16/12、
192.168/16），按**网卡名黑名单**挡掉 Docker / 容器 / 虚拟网卡（如 `br-`、`docker`、`veth`），
不再按地址段误伤 172.x 的真实 Wi-Fi；物理网卡按接口名优先级排序。这保证插件列出的局域网链路
与手机实际拿到的候选一致。

**插件单独配置的手填链路与局域网链路严格分开**：即使手填地址与某条局域网网卡地址完全相同
（例如都是 `10.19.9.3`），也各算一条、来源不同（`plugin-config` vs `nic`）、id 不同，面板上分组
显示、策略里分别控制。因为 dsh-mobile-plugin 里手填直连是独立通道，与网卡候选的处理不同。

## 三种模式

- **局域网优先**：局域网链路健康就用它（多条网卡按实测 RTT 择优）；不健康时依次退到 Tailscale
  网卡线路（lan-ts）、插件手填链路、DSH 直连隧道、中转。局域网恢复后会抢回。
- **自动择优**：对每条链路算综合分——质量（RTT 的指数移动平均）+ 稳定性（可用率、抖动），
  按可调权重合成。新链路必须比当前高「切换优势阈值」、且过了最短驻留时间才切换；10 分钟内被
  切太多次的链路会暂时拉黑，抑制来回横跳。
- **手动顺序**：完全按面板上勾选并排序的链路走；前一条连续不健康（次数由阈值决定）才让位。

三种模式共用同一套健康判据：探测失败，或 RTT 超过该链路所属组的「降级阈值」，算不健康。
**不健康不等于立刻切**——要连续达到「连续失败次数」才降级，否则一次抖动就会把手机推到更慢的
线路上；恢复到「恢复阈值」以下才切回来。

## UI 设置界面

打开 `http://127.0.0.1:3080/dsh-mobile-route/panel`（端口按实际 DSH Web 端口）：

- 顶部：当前生效链路、原因、上次探测、插件状态；
- **可用链路**：按「局域网网卡 / 局域网·Tailscale 网卡 / 插件手填链路 / DSH 内置隧道 / 中转」
  分组，每条显示实时 RTT、均值、抖动、可用率与状态；顶部有两条 Tailscale 线路分离的提示；
- **手动模式**：
  - 切换「单选 / 多选排序」；
  - 单选：点一条链路即只用它；
  - 多选排序：勾选多条链路，**拖拽条目**（或用 ↑↓ 按钮）调整优先级，可随时加入 / 移除；
- **自动模式**：质量权重、稳定性权重、切换优势阈值、10 分钟限抖次数、最短驻留时间；
- **健康阈值**：每条链路组的降级 / 恢复阈值与连续失败次数；
- 三个开关：允许关隧道、自动重启 sidecar、观察模式；最近 60 条事件。

「观察模式」只计算不执行，适合先看几天它想切到哪，确认判断合理再切到执行。

## 安全护栏

关掉直连隧道是逼手机走局域网的唯一手段，也是唯一能让手机彻底连不上的动作。所以它有四道闸：

1. `allowDisableTailcat` 打开；
2. 目标局域网链路**实测健康**；
3. 手机最近确实通过局域网连过（读 `relay-device-credentials.json` 的 `lastChannel`）；
4. 局域网入口近期没有崩过——每次自愈后 10 分钟内算「不稳」。

缺一条就保持隧道开着，并在面板上写明是哪一条拦下的。手填 TCP 直连若指向 Tailscale 网段，
在选局域网时会被一并收掉；其它地址不动。

局域网入口（sidecar）挂掉时按限频（默认 30 秒）调用 `/api/relay/restart-sidecar` 自愈。

**自愈健康判据与看门狗**：兼容 dsh-mobile-plugin 新旧版本的 status 结构——只有在**明确**
读到故障态（`error`/`stopped`/`failed`/`down` 等）、且没有任何局域网链路实测可达时，才判定
入口故障。字段缺失或未知值一律视为健康，避免旧代码把 `lan.state` 缺失误判成故障、每轮都
重启 sidecar 把移动连接反复拖断。另有看门狗：滑动窗口（默认 10 分钟）内重启超过上限
（默认 3 次）就熔断，暂停自动重启（默认 15 分钟），并在面板显示状态；可用「解除自愈熔断」
按钮或 `reset` / `reset-watchdog` 动作手动恢复。

## 自动重启守护（彻底解决反复"请重启 DSH"）

**根因**：dsh-mobile-plugin 默认自动更新。每次后台升级到新版后，新代码被热加载进正在运行的
DSH，但它的**外壳（host 侧）/隧道/镜像初始化只在进程启动时装载**——于是出现"磁盘版本 > 运行
版本"、`shellChanged`、镜像不推送，手机端反复报"解不开 / 请重启"。你重启一次就好，下次自动
更新又复现——这就是反复出现的死循环。

**本插件的彻底解法**（默认开启）：

1. **启动时自动关闭 dsh-mobile-plugin 的自动更新**（写
   `storages/mobile-plugin/auto-update.json` = `{"enabled": false}`，幂等）。版本不再被偷偷升级，
   从根上杜绝"热加载未重启"。
2. **自动重启守护**：每 60 秒检查一次，当发现"磁盘版本 ≠ 运行版本"、`shellChanged` 或
   `firstInstallPendingRestart` 时，用独立 helper 进程自动重启 DSH（等旧进程退出 → 等端口释放 →
   同参数拉起 → 等端口恢复）。带 90 秒启动宽限期 + 24 小时内最多 2 次的熔断，避免重启循环。
3. 面板顶部显示守护状态（磁盘/运行版本、自动更新是否关闭、最近判定），并提供「立即重启 DSH」
   按钮；开关「自动重启守护」可关闭此行为。

`/api/relay/reload-implementation` 只能换"实现"，换不了"外壳"，所以解决不了这个问题——必须重启
宿主，这也是守护选择重启而非 reload 的原因。

**代价**：关闭自动更新后，以后 dsh-mobile-plugin 出新版本需要手动更新并重启一次；但因为守护
仍在，更新后它会自动完成那次重启，不需要你手动操作。

## 接口

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/dsh-mobile-route/state` | 配置、链路清单、各链路状态、当前决策、事件 |
| POST | `/dsh-mobile-route/config` | 改配置（`mode` / `selection` / `autoPolicy` / `thresholds` 等） |
| POST | `/dsh-mobile-route/action` | `probe` / `heal` / `reset` |
| GET | `/dsh-mobile-route/panel` | 配置面板 |

## 已知限制

- **手机端仍有自己的判断**：本插件编排电脑侧上报的候选与隧道开关，手机 App 怎么合并、何时
  重新探测不在控制范围内。它做的是持续把「正确的答案」摆在手机面前。
- **直连隧道的时延量不到**：电脑侧只能读插件报的 ready 状态，它不参与速度比较，只作兜底。
- **`preferredLanAddress` 只能调网卡候选的顺序**：dsh-mobile-plugin 里它匹配不上就不生效，
  所以多条局域网链路的优先级通过「选哪条 + 组内 RTT 择优」表达，不能凭空新增网卡地址；要新增
  地址请在 dsh-mobile-plugin 里配置手填链路，它会作为 `manual:*` 独立出现在面板上。
- **Tailscale 网卡地址只识别 `100.64.0.0/10`**，且必须通过 `manualLanUrl` 上报（dsh-mobile-plugin
  的网卡候选只认 RFC1918，不会自动上报 100.64 地址）。它与 DSH 内置隧道是两条独立线路。
- 配置持久化走 profile 的 configEditor，改完插件会重启一次，内存里的探测历史会清空。

## 打开面板

- 直接访问 `http://127.0.0.1:3080/dsh-mobile-route/panel`（端口按实际 DSH Web 端口）。
- fnOS 上从侧边栏左下角 **「飞牛 OS」菜单**里选「手机连接选路」，在新标签页打开面板。
- 插件同时在侧边栏插件行注册了同一入口（是否直接显示取决于宿主的插件行 pin 设置）。
